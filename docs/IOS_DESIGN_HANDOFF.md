# S.tand iOS → Android 디자인·제품 인수인계

상태: 최신 기준 요약

기준일: 2026-08-12 KST

iOS 기준: `main` / `0f664b2`

iOS 버전: `1.0.0 (0.24.1)`

이 문서는 작업 시작용 요약이다. 구현·검수의 단일 전체 기준은 iOS 저장소의
`docs/ANDROID_IMPLEMENTATION_HANDOFF.md`이며, Android 실행 명세는
`IOS_TO_ANDROID_TECHNICAL_RECIPE.md`, 실제 확인 상태는 `IOS_PARITY.md`에 기록한다.
과거 `24f1ec2 / 0.23.3` 전달본과 그 문서에서 파생한 완료 판정은 최신 기준이 아니다.

## 기준 우선순위

1. iOS `PROJECT_RULES.md`
2. 기준 커밋의 실제 Swift 소스와 XCTest
3. iOS `docs/DESIGN_RECIPE.md`
4. iOS `docs/INTERNET_RADIO_BUTTON_DESIGN_SPEC.md`
5. iOS `docs/ANDROID_IMPLEMENTATION_HANDOFF.md`
6. 이 저장소의 기술 레시피와 동등성 문서

## 전체 화면과 진입점

- 홈, 홈 정보 패널 편집, 수면 소리, 설정
- 시계 글꼴 선택, 폰트 저작권 목록, 글꼴별 라이선스 상세
- 설정 안의 라디오 인라인 관리·편집
- 별도 라디오 채널 목록 관리, 채널 추가·수정
- 라디오 앱 내부 전체 화면 브라우저
- 라디오·녹음 삭제 확인과 오류 안내
- 일반 실행, 위젯과 `stand://open`, Sharesheet `ACTION_SEND/text/plain`
- 홈 라디오 탭 재생·정지, 홈 라디오 길게 눌러 편집
- 편집 중 빈 두 번째 라디오 패널에서 채널 관리 진입
- 브라우저 진입 3곳: 설정 라디오 카드, 채널 관리, 채널 추가·수정

위 화면이나 진입점이 없으면 동등성 완료로 표시하지 않는다. Android에서 한 화면으로 통합한
경우에도 사용자 흐름이 모두 도달 가능한지와 그 플랫폼 차이를 기록한다.

## 제품·디자인 불변 조건

- 상태명은 `오브제 모드`, `매이트 모드`, `화들짝 모드`로 고정한다.
- 오브제에서는 마이크·녹음·반복 카메라·플래시를 중지한다.
- 앱 조명과 시스템 밝기를 분리하며 시스템 밝기를 쓰지 않는다.
- 홈은 상단 모드/브랜드/배터리, 정보 패널, 하단 `수면 소리`/`설정`으로 구성한다.
- 패널은 iOS `FlipPanelSurface`의 따뜻한 저투명 흰색 그라데이션과 약한 테두리를 따른다.
- 오렌지·그레이·미드나이트·세이지 4개 테마, 12시간제, 독립 초 패널을 유지한다.
- 날씨와 라디오 패널은 40% 이상 겹치면 결합한다. 날씨는 더블 탭, 묶인 라디오는 한 번 또는 두 번 눌러 분리한다.
- 방향별 위치와 30~200% 크기, 중심선 5% 자석, 저장 전 초안/취소를 보존한다.
- 설정 순서는 Hero → 라디오 → 화면과 시계 → 권한 → 잠꼬대와 코골이 → 정보다.
- 계정·서버·광고·분석·클라우드 업로드를 추가하지 않는다.

## 라디오와 앱 내부 브라우저

- 사용자 제공 HTTPS 직접 스트림만 최대 2개 저장한다.
- 재연결은 `2, 4, 8, 15, 30초`, 최대 5회다.
- 재생·연결 중 마이크 감지와 녹음을 쉬고 움직임 감지는 유지한다.
- 사용자 정지·채널 변경·삭제는 이전 재연결을 취소한다.
- 오디오 인터럽션은 시스템이 재개를 허용한 경우에만 복구한다.
- 활성 채널의 URL 변경·삭제는 재생을 중지하고 이름 변경만으로는 중지하지 않는다.
- 삭제는 확인 후 실행하며 부분 실패를 실제 저장 상태와 다시 동기화한다.

브라우저는 독립 전체 화면이다. Google 홈, 주소·검색, 이동/중지, 새로고침, 뒤로/닫기,
즐겨찾기를 제공한다. 기본 즐겨찾기는 Google, 한국 라디오, FMSTREAM, Radio Browser 순서다.
HTTPS와 유효 host만 허용하고 credential, HTTP, custom scheme, 다운로드, 첨부, 파일 업로드,
웹 카메라·마이크·모션·위치 권한을 거부한다. 팝업은 같은 WebView에서 열고 앱 비활성·화면
이탈 시 미디어를 멈춘다. 웹페이지를 분석해 스트림 주소를 감지·전달·저장하지 않는다.

## 0.24.0 안정성 추가 기준

- 카메라 관찰 1초, 결과 유효 60초, 반복 45초와 전환 재확인
- 라디오 최대 5회 재연결과 인터럽션 복구 조건
- 연속 큰 소리 pending 녹음 최대 4개
- 디코딩 불가 설정 payload를 사용자 변경 전까지 원본 보존
- 위치 기능 종료 시 날씨·위치명·갱신 시각 제거와 요청 generation 차단
- 센서 stop 후 과거 callback generation 차단
- 단일·일괄 삭제 실패와 부분 성공 후 상태 재동기화
- 홈·편집·브라우저 접근성 동작과 큰 글자 재배치
- Privacy Manifest/Data Safety와 실제 파일 timestamp 사용 일치

## Android 플랫폼 대응

| iOS | Android | 유지할 의미 |
|---|---|---|
| SwiftUI | Jetpack Compose | 화면·상태·접근성 흐름 |
| WKWebView | WebView | HTTPS·권한·다운로드·미디어 정책 |
| Safari 공유 확장 | `ACTION_SEND/text/plain` | 검증된 URL 한 건을 저장 전 초안으로 전달 |
| AVAudioSession | AudioFocus/AudioManager | 인터럽션·재개 조건과 라디오/마이크 상호배제 |
| CoreMotion | SensorManager | stop 이후 과거 callback 차단 |
| 대략적 위치 | coarse location | 최소 권한과 오래된 요청 차단 |
| iOS 로컬 저장 | 앱 내부 파일·SharedPreferences | 무업로드·백업 제외·손상 데이터 보존 |

## 완료 판정

소스 존재만으로 완료 처리하지 않는다. 구현, JVM/단위, UI/계측, 실기기, iOS 역대조의 증거를
`IOS_PARITY.md`에 각각 기록한다. 직접 실행하지 않은 UI·기기 항목은 `대기`로 남긴다.
