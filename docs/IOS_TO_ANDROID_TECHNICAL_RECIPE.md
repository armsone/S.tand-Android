# S.tand iOS 0.24.1 → Android 구현 기술 레시피

기준일: 2026-08-12 KST

iOS 기준: `0f664b2`, `1.0.0 (0.24.1)`

Android 현재 후보: versionName `0.0.1`, versionCode `29`, 빌드 표기 `0.0.29`

상위 전체 기준은 iOS `docs/ANDROID_IMPLEMENTATION_HANDOFF.md`다. 이 문서는 Android 구현 위치와
검증 방법을 고정한다. 과거 `0.23.3` 레시피의 누락이나 완료 표시는 사용하지 않는다.

## 1. 구조와 책임

| 책임 | Android 위치 | 원칙 |
|---|---|---|
| 설정·마이그레이션 | `data/SettingsRepository.kt` | 원자 저장, 레거시 호환, 손상 원본 보존 |
| 제품 상태 | `StandViewModel.kt` | 모드·센서·오디오·라디오의 단일 조정자 |
| 순수 정책 | `model/*`, `audio/AudioAnalysis.kt` | 프레임워크 없이 JVM 검증 |
| 홈·편집 | `ui/StandHomeScreen.kt`, `ui/ScreenEditorScreen.kt` | 표시·제스처만, 정책 중복 금지 |
| 설정·라디오 | `ui/SettingsScreen.kt`, 라디오 관리/편집 화면 | 세 진입점과 삭제 확인 보존 |
| 브라우저 | `ui/InternetRadioBrowserScreen.kt` | WebView와 수명주기·보안 격리 |
| 녹음 | `recording/*`, `ui/RecordingsScreen.kt` | 승인 파일만 공개, 부분 실패 재동기화 |
| 플랫폼 | `platform/*`, `weather/*` | 세대·권한·수명주기 방어 |

Compose가 저장소·센서를 직접 호출하지 않는다. 화면 이벤트는 ViewModel로 보내고 상태는 단방향으로
수집한다. 기존 라디오 저장·재생 인터페이스를 우회하거나 중복 구현하지 않는다.

## 2. 화면·진입점 라우팅

필수 화면은 홈, 정보 패널 편집, 수면 소리, 설정, 글꼴 선택, 폰트 라이선스 목록/상세,
설정 인라인 라디오, 채널 목록 관리, 채널 추가·수정, 전체 화면 브라우저, 삭제 확인/오류다.

필수 진입점:

1. 일반 실행, 위젯, `stand://open`
2. `ACTION_SEND/text/plain` HTTPS 초안
3. 홈 라디오 탭 재생·정지와 길게 눌러 해당 채널 편집
4. 편집 중 빈 두 번째 라디오 패널에서 채널 관리
5. 설정 카드 → 브라우저
6. 채널 관리 → 브라우저
7. 채널 추가·수정 → 브라우저

회전·600dp 전환에서 편집 초안, 라디오 편집 입력, 브라우저 history를 잃지 않는다. Android에서
화면을 통합하면 세 사용자 흐름이 모두 도달 가능한지 별도 UI 테스트로 증명한다.

## 3. 모드·앱 조명·홈 제스처

- 저장 상태: `AUTOMATIC/OBJECT/MATE`, 실제 환경 `OBJECT/MATE`, 표시 `OBJECT/MATE/STARTLED`.
- 일반 홈 전체 더블 터치는 테마를 순환하고, 전체 핀치는 시계 크기를 0.70~1.35로 조절한다.
- 앱 조명 40% 경계, 35/80 원터치 2초 전환, 0/100% 1초 유지 잠금.
- 95~100% 손떼기 역방향은 오브제 잠금을 취소하지 않는다.
- 시스템 밝기는 초기 참고값으로만 읽고 쓰지 않는다.
- 세로 드래그와 탭·롱프레스·라디오 입력을 동시에 판정하지 않는다.
- 홈 앱 조명은 TalkBack adjustable action을 제공한다.
- 오브제에서는 마이크·녹음·반복 카메라·플래시를 중지한다.
- 배경·비활성·20% 이하 비충전 보호에서 센서·마이크·카메라·플래시·라디오를 정리한다.

## 4. 패널·편집·디자인

- 테마 4개, 12시간제, 독립 초, 방향별 레이아웃을 유지한다.
- 날씨 3조각과 라디오 2패널은 작은 쪽 면적의 40% 이상 겹치면 결합한다.
- 이동은 화면 경계로 제한하지 않고 크기만 30~200%로 제한한다.
- 중심선 5% 자석, 중심 유지 크기 조절, 방향별 최신 기본값을 사용한다.
- 초기화는 초안만 바꾸고 취소는 폐기, 저장은 한 번에 영속화한다.
- 편집 접근성은 이름/크기 읽기, 5% 방향 이동, 10% 확대·축소, 열기 action을 제공한다.
- 하단 버튼은 `수면 소리`, `설정` 고정이며 순서 편집 UI를 노출하지 않는다.

## 5. 설정 정보 구조와 권한

순서는 Hero → 인터넷 라디오 → 화면과 시계 → 권한 → 잠꼬대와 코골이 → 정보다. 테마 위의 밝은
유리 카드와 실제 플립 글꼴 미리보기를 사용한다. OS grant와 앱 내부 사용 설정을 구분하며 영구
거부는 시스템 앱 설정으로 안내한다. 추천 설정 복원은 범위를 설명하고 확인한다.

## 6. 라디오 채널·재생

- HTTPS, host 필수, credential 금지, 이름 30자, 주소 2,048자, 최대 2개.
- 첫째/둘째 채널을 홈 첫째/둘째 패널에 연결한다.
- 상태: `대기`, `연결 중`, `다시 연결 중`, `재생`, `연결 실패`.
- 재시도 간격 `2, 4, 8, 15, 30초`, 최대 5회. 성공 시 횟수를 초기화한다.
- 사용자 정지·채널 전환·삭제·URL 변경은 pending retry를 취소한다.
- 이름만 변경하면 활성 재생을 유지한다.
- AudioFocus 손실에서는 멈추고, 시스템이 재개를 허용한 경우만 동일 채널을 복구한다.
- 백그라운드와 출력 장치 분리에서 중지한다.
- 연결·재생 중 마이크 감지/녹음을 쉬고 움직임 감지는 유지한다.
- 삭제 전 이름과 URL 복구 불가 범위를 확인한다. 부분 실패는 저장소를 다시 읽어 UI와 맞춘다.

## 7. 앱 내부 브라우저

세 진입점은 설정 라디오 카드, 채널 관리, 채널 추가·수정이다. 브라우저는 채널 편집기로 주소를
전달하지 않고 사용자가 복사·붙여넣기를 명시적으로 수행한다.

상단 순서: 44/48dp 뒤로·닫기 → 44~56dp 주소창 → 이동/중지 → 새로고침 → 즐겨찾기.

- Google 홈, scheme 없는 도메인과 일반 검색어 지원, 일반 검색은 Google URL로 변환.
- 이동 버튼 0.5초 길게 눌러 클립보드 문자열을 붙여넣고 이동.
- history가 있으면 뒤로, 없으면 닫기; 길게 누르면 즉시 닫기.
- 팝업은 같은 WebView에서 열고 닫을 때 원래 페이지 복귀.
- 1dp 구분선, 2dp 진행선, 큰 글자에서도 최소 터치 영역 유지.
- 기본 즐겨찾기: Google, 한국 라디오, FMSTREAM, Radio Browser.
- HTTPS/host만 허용. credential, HTTP, `file:`, `blob:`, custom scheme를 거부.
- 다운로드·attachment·표시 불가 MIME, 파일 선택/업로드/드롭/클립보드 파일을 거부.
- 웹 카메라·마이크·모션·위치와 HTTP 인증을 거부하고 SSL 검증을 우회하지 않는다.
- `allowFileAccess=false`, `allowContentAccess=false`, mixed content 금지, cleartext 금지를 유지한다.
- 스트림/HLS/ICY/DOM/네트워크를 분석해 주소를 찾지 않는다.
- 앱 비활성·화면 이탈 시 페이지 미디어를 멈춘다.
- history, popup, renderer 종료, 회전, 뒤로가기, 미디어 중지를 계측/실기기로 검증한다.

## 8. 공유 수신

브라우저와 별도다. `ACTION_SEND`, `text/plain`, URL 한 개만 받고 라디오 저장 정책과 같은 HTTPS
검증을 거친다. `ACTION_VIEW` 브라우저 필터는 추가하지 않는다. 최신 한 건을 저장 전 초안으로
보여 주고 사용자가 저장하거나 버린다.

## 9. 자동 판단·카메라·센서·화들짝

- 일반 확인: 어두워짐 20초, 밝아짐 35초. 최신 카메라 어두움 판정은 4초 뒤 재확인.
- 카메라 1초 관찰, 어두움 0.16, 밝음 0.28, 결과 유효 60초, 반복 45초.
- 오브제에서는 반복 카메라를 중지하고 사진·영상을 저장하지 않는다.
- 화들짝은 5초 유지 후 30초 복귀. 일반 터치는 플래시를 켜지 않는다.
- 플래시는 최근 60초 내 0.16 이하, 사용자 설정, 하드웨어 조건이 모두 맞을 때만 사용한다.
- 센서 start마다 generation/token을 만들고 stop에서 무효화한다. main queue에 남은 callback도
  captured generation과 현재 generation이 다르면 버린다.

## 10. 감지·녹음·세션

- 전경+매이트+마이크 사용+라디오 미재생+배터리 보호 비활성에서만 작동한다.
- 60초 적응형 기준, 코골이 0.58/잠꼬대 0.60 이상만 후보 보존.
- pre-roll 0.8초, post-roll 1.4초, segment 90초, AAC-LC M4A 약 48kbps.
- 승인 전 staging, 승인 뒤 atomic move, 앱 시작 시 stale staging 정리.
- 연속 큰 소리의 pending segment는 최대 4개. 다섯 번째를 열지 않고 현재 후보를 안전하게 끝낸다.
- stop, 권한 철회, route 변경, writer 오류에서 승인 전 파일을 모두 폐기한다.
- 오디오 인터럽션은 시스템 재개 허용 시에만 감시를 복구한다.
- 매이트 이탈 후 30분 이내 재진입은 같은 세션, 레거시는 90분 간격으로 추정한다.

## 11. 녹음 화면·파일 작업

- 세션 timeline에 녹음 marker와 화들짝 구간을 표시하고 목록은 기본 접힘이다.
- 선택, 재생/일시정지, 탐색, 공유, 단일/선택/전체 삭제를 제공한다.
- 병합은 시간순+0.5초 무음, 첫 원본 시간 제목, 기본 원본 보존이다.
- 병합 중 삭제와 선택 변경을 막는다.
- 삭제 성공 파일만 session manifest에서 제거한다. 부분 실패 시 reload 후 실패 파일을 남기고 오류를
  표시한다. 파일 없음도 실제 상태와 동기화한다.
- 큰 글자는 카드와 dock을 두 행/세로로 재배치하고 최소 터치 영역을 유지한다.

## 12. 날씨·위치

- coarse location과 마지막 성공 날씨를 사용하며 실패해도 시계와 다른 패널을 유지한다.
- request generation으로 오래된 위치/날씨/geocode 결과가 최신 상태를 덮지 못하게 한다.
- 위치 기능을 끄면 요청을 무효화하고 날씨, 위치명, 갱신 시각, 진행 상태를 즉시 지운다.
- 긴 위치명은 아이콘 고정+텍스트 왕복 marquee다.

## 13. 설정 저장·복구

- 레거시 단일 라디오, UUID 선택, 방향별 레이아웃을 호환 이전한다.
- 디코딩 불가 미래/손상 payload는 추천값으로 즉시 덮어쓰지 않는다.
- 원본 payload를 사용자가 실제 설정을 변경할 때까지 보존한다.
- 최초 마이그레이션은 사용자의 이후 선택을 다시 덮지 않는다.

## 14. 개인정보·백업·접근성

- 녹음과 설정은 앱 내부에 두고 cloud backup/device transfer에서 제외한다.
- 계정·광고·분석·업로드를 추가하지 않는다.
- Data Safety에는 실제 권한/API, 로컬 저장과 외부 서비스 전송을 구분하고 파일 timestamp
  metadata 사용을 기록한다. 저장소 근거는 `ANDROID_DATA_SAFETY.md`로 유지한다.
- TalkBack은 모드·선택·라디오·권한·오류를 중복 없이 읽는다.
- 브라우저의 뒤로/닫기, 이동/중지, 붙여넣기 이동, 새로고침, 즐겨찾기를 구분한다.
- 색상만으로 상태를 전달하지 않고 44/48dp 터치 영역을 유지한다.

## 15. 필수 자동 검증

- 주소/공유 HTTPS·credential·길이, 4개 즐겨찾기.
- 재연결 5회와 정확한 지연, 정지/전환/삭제 retry 취소, AudioFocus 복구 조건.
- pending segment 4개 상한과 중지/오류 정리.
- 손상 설정 원본 보존과 사용자 변경 후 교체.
- 날씨 generation·비활성 캐시 제거, 센서 generation.
- 단일/선택/전체 삭제의 성공·부분 실패·manifest 동기화.
- 브라우저 history/popup/renderer/권한/다운로드/업로드/회전/미디어.
- 홈 조명·편집 패널·브라우저 접근성과 큰 글자.

완료 전 `testDebugUnitTest`, `assembleDebug`, `lintDebug`를 실행한다. UI/계측과 실기기 항목을
실행하지 않았다면 성공으로 추정하지 않고 `IOS_PARITY.md`에 대기로 남긴다.
